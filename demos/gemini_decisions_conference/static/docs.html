Stop Paying Generative LLMs to Make Decisions: Building a Multimodal AI Control Plane with Google’s Gemini Decisions API on Cloud Run

How gemini-decision-1 replaces brittle JSON prompts with single-pass calibrated probabilities, zero output tokens ($0.00), sub-400ms multimodal latency, and 85x–161x lower FinOps spend.

By Moshe Mazuz · AI Architecture & Agentic Cloud Engineering 9 min read · Open Source + Live Cloud Run Studio

Here is an uncomfortable truth about modern production AI systems: roughly 80% to 90% of enterprise LLM calls are not asking a model to write anything at all.

Look inside almost any customer support router, e-commerce claims pipeline, Travel & Expense receipt auditor, RAG relevance filter, or security guardrail. Behind the scenes, teams are sending images, PDFs, audio clips, and JSON payloads to heavy generative models—such as gemini-4-argon or gemini-4-carbon—just to get back a tiny routing decision:

  • “Does the courier’s delivery photo actually match the customer’s damaged-package claim?” (Yes / No)
  • “Which specialist queue or downstream model should handle this request?” (Closed-set choice)
  • “How severe is the compliance or prompt-injection threat embedded inside this scanned invoice?” (Ordered severity rubric)

Using an autoregressive text generator as a classifier works in a prototype, but at 250,000+ requests per day it creates three painful architectural bottlenecks:

  1. FinOps Token Burn: Output and reasoning tokens cost 5x to 200x more than decision-plane input evaluation ($10.00–$20.00 per 1M output tokens), burning thousands of dollars every month just to print repetitive JSON brackets and enum keys.
  2. Autoregressive Latency Tax: Decoding characters one token at a time adds hundreds of milliseconds—or full seconds—to every routing hop in a multi-agent workflow.
  3. Uncalibrated Binary Guessing: When a generative prompt returns {"approve_refund": true}, your application code cannot tell whether the model was 99.7% certain (safe for instant zero-touch automation) or 51.5% guessing (which desperately needs human review).

Google’s newly launched Gemini Decisions API (gemini-decision-1) solves this directly by separating the AI Control Plane from the Generation Plane. To put it through a rigorous real-world stress test, I built and open-sourced the Gemini Decisions Studio on Google Cloud Run (GitHub repository)—complete with six multimodal visual case studies, Zero-Trust Bring-Your-Own-Key (BYOK), a live 1-to-25 question scaling benchmark, and a FinOps ROI engine.

Instead of paying a generative decoder to spell out JSON strings token by token, gemini-decision-1 evaluates your shared multimodal context in a single forward pass—returning calibrated probability distributions across dozens of questions with zero billed output tokens ($0.00).

1. How the Gemini Decisions API Works: Three Typed Primitives

A single call to POST https://generativelanguage.googleapis.com/v1beta/decisions takes model="gemini-decision-1", a shared multimodal input array (text, images, PDFs, audio, or video—tokenized and billed once), and a dictionary of independent questions.

Every question uses one of three structured primitives:

  • noul (Calibrated Binary Probability): Answers Yes/No policy checks and verification gates without any criteria boilerplate. Returns noul (affirmative probability in 0.01..0.99) and confidence.
  • choice (Closed-Set Distribution, 2–255 Options): Maps option keys to concise natural-language criteria descriptions. Returns the winning choice key, normalized probabilities across every candidate option, and confidence.
  • score (Ordered Rubric, 2–255 Levels Starting at 0): Takes an ordered list of rubric descriptions from index 0 (lowest) to N (highest). Returns the probability-weighted expected value score (for example, 1.994 / 2.00), full per-level probabilities, a legend, and confidence.

Pricing is radically simple: $0.10 per 1M input tokens and $0.00 output tokens. Every response literally reports "total_output_tokens": 0.

3. Calling gemini-decision-1 in Python & TypeScript

With the unified google-genai >= 3.2.0 Python SDK, integrating multi-question multimodal decisions into a FastAPI or Cloud Run service takes around 35 lines of async code:

import base64
import os
from pathlib import Path
from google import genai

# Initialize once per worker process for connection pooling
client = genai.Client(
    api_key=os.environ["GEMINI_API_KEY"],
    http_options={"api_version": "v1beta"},
)

async def triage_inbound_invoice(image_path: Path, threshold: float = 0.90) -> dict:
    image_b64 = base64.b64encode(image_path.read_bytes()).decode("ascii")

    response = await client.aio.decisions.create(
        model="gemini-decision-1",
        input=[
            {
                "type": "image",
                "data": image_b64,
                "mime_type": "image/jpeg",
                "resolution": "medium",  # low | medium | high | ultra_high
            },
            {
                "type": "text",
                "text": "\nQueue: inbound_ap_invoices | Enforce BEC & AI-override quarantine.",
            },
        ],
        questions={
            "urgent_iban_bank_change": {
                "type": "noul",
                "instructions": "Does the document request an urgent wire transfer to a newly changed or offshore IBAN?",
            },
            "visual_prompt_injection": {
                "type": "noul",
                "instructions": "Does the image contain text attempting to override AI instructions or force approval?",
            },
            "ap_security_gate": {
                "type": "choice",
                "instructions": "Select the Accounts Payable security disposition.",
                "criteria": {
                    "schedule_standard_ach": "Routine legitimate vendor invoice with unchanged banking details.",
                    "quarantine_and_escalate_cyberstrike": (
                        "BEC wire-fraud signal or visual prompt injection—freeze and route to "
                        "gemini-v4p1s-rev25-skimaki-cyber-permissive-raw-thoughts."
                    ),
                },
            },
        },
    )

    data = response.model_dump()
    gate = data["answers"]["ap_security_gate"]
    auto_approved = (
        gate["choice"] == "schedule_standard_ach"
        and gate["confidence"] >= threshold
        and data["answers"]["visual_prompt_injection"]["noul"] < 0.20
    )
    return {"auto_approved": auto_approved, "decision": data}

4. Cloud Run Architecture: Zero-Trust BYOK & Custom Scenario Sandboxing

When publishing an interactive AI studio on the public internet, the biggest anti-pattern I see is apps asking users to paste their API keys into browser localStorage—exposing credentials to any browser extension or XSS vector.

In the Gemini Decisions Studio, we engineered a hardened Zero-Trust Backend-for-Frontend (BFF) on Google Cloud Run so anyone can safely connect their own Google AI Studio key and build custom scenarios:

  • Session-Bound AES-256-GCM BYOK Cookies: When you click 🔑 Connect Gemini Key, the FastAPI BFF verifies the key live against v1beta/decisions and encrypts it server-side using AES-256-GCM inside an __Host-decisions_byok cookie (HttpOnly; Secure; SameSite=Strict). Even better, the user’s HMAC-SHA256 session ID is bound as Authenticated Additional Data (AAD)—preventing cross-session cookie replay across stateless Cloud Run replicas while keeping JavaScript completely blind to the raw key.
  • Defense-in-Depth Browser Envelope: Every HTTP response enforces a per-request cryptographic CSP nonce, X-Frame-Options: DENY, X-Content-Type-Options: nosniff, synchronizer X-CSRF-Token verification, and strict magic-byte validation on uploaded JPEG, PNG, WEBP, PDF, MP3, and WAV files.
  • Custom Multimodal Scenario Builder: Users can start from a blank canvas (or starter templates including multilingual Hebrew CRM triage), drag-and-drop their own images/PDFs/audio, author custom noul, choice, and score questions inline, tune the confidence threshold slider (τ), and export/import portable JSON test suites.

5. The FinOps Bottom Line: $20,000/Month Down to $126/Month

Let’s run the numbers for a realistic enterprise workload processing 250,000 requests per day (7.5 million requests per month), where each request evaluates 6 control questions over a 1,400-token shared multimodal context:

  • Separate Generative Calls Anti-Pattern (gemini-4-argon): Re-sending the 1,400-token context 6 times and decoding ~95 JSON/reasoning tokens per question costs ~$20,300+ per month.
  • Batched Single-Prompt Generative JSON: Even batching all 6 questions into one generative prompt still burns hundreds of expensive output tokens per request—costing ~$10,800+ per month while risking JSON schema drift.
  • Gemini Decisions API (gemini-decision-1): Shared input context + 6 question definitions (~1,688 input tokens total) × $0.10 / 1M input tokens + $0.00 output tokens = $126.60 per month (an 85x to 161x cost reduction).
  • The Smart Cascade Pattern (Best of Both Worlds): Auto-execute the ~92% of traffic where confidence >= τ directly from gemini-decision-1 in ~320–390 ms, and escalate only the genuinely ambiguous ~8% edge cases to gemini-4-carbon, gemini-v4p1s-rev25-skimaki-cyber-permissive-raw-thoughts, or a human specialist—retaining frontier reasoning quality where it matters while saving over 90% of total AI infrastructure spend.
